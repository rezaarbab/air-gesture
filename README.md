# اشاره — Air Gestures

کنترل گوشی با حرکت سر و دست در هوا، بدون لمس صفحه. یک APK، سه حالت، یک راه اجرا.

| حالت | منبع | چه می‌دهد |
|---|---|---|
| **نشانگر** | دوربین جلو + `FaceLandmarker` (۴۶۸ لندمارک) + `HandLandmarker` | سر = مکان‌نمای ماوس، پینچ = کلیک، پینچ نگه‌داشته + حرکت = کشیدن، دو پینچ = تنظیم نقطهٔ مرجع، پلک = کلیک اختیاری، توقف روی چیزها = «حلقهٔ آب» و کلیک |
| **دست** | دوربین جلو + `HandLandmarker` | دست بالا/پایین، پینچ، دو پینچ، کف باز ثابت |
| **سنسور** | `TYPE_PROXIMITY` | یک موج، دو موج، پوشاندن طولانی |

تشخیص همه‌جا روی دستگاه است (TFLite، آفلاین). لمس از
`android.accessibilityservice.GestureDescription` و `AccessibilityService.dispatchGesture()`
می‌آید — همان مسیری که انگشت می‌رود، پس اینستا و بقیه فرقی را نمی‌فهمند.

## چرا این‌جوری ساخته شد

اندروید (و iOS) هیچ API عمومی برای «حرکت در هوا» ندارند؛ تنها استثناها سخت‌افزار-خاص بودند:
رادار Soli در Pixel 4 (حذف شد)، S Pen Air Actions، Air Actions روی ساعت. پس تشخیص را باید خودت
بسازی: دوربین → مدل → تصمیم → لمس تزریقی.

**مکان‌نمای سرعتی، نه موقعیتی.** سر به هر طرف که برود نشانگر با سرعت آنجا حرکت می‌کند و وقتی سر
به نقطهٔ مرجع برگشت، نشانگر می‌ایستد. این همان کاری است که تکنولوژی کمکی (Mouse Hat، Camera Mouse)
سال‌هاست می‌کند: کنترلِ موقعیت مستقیم با سر، لرزش و «پرش» می‌آورد. از همین رو «دو پینچ» نقطهٔ
مرجع را روی وضعیت فعلی سر تنظیم می‌کند.

**حلقهٔ آب (dwell).** برای اینکه حلقه دور *خودِ دکمه* بپیچد و کلیک همان‌جا بخورد، سرویس درخت
`AccessibilityNodeInfo` پنجرهٔ فعال را می‌خواند و عمیق‌ترین گرهٔ زیر مکان‌نمای را پیدا می‌کند.
یعنی این سرویس علاوه بر تزریق لمس، ساختار صفحه را هم می‌بیند؛ اپ‌هایی که درخت ندارند (بازی، Canvas،
برخی فریم‌ورک‌ها) فقط نقطهٔ مکان‌نما را می‌گیرند. با «فقط روی دکمه‌های واقعی توقف کن» می‌توان
کلیک روی جای خالی را بست.

## سرعت

دو مسیر پیکسل در اپ هست و با سوئیچ «فرمت فریم» در خانه انتخاب می‌شود:

- **JPEG (پیش‌فرض):** `ImageReader(JPEG)` → `BitmapFactory` → چرخش فیزیکی بیتمپ → `BitmapImageBuilder`.
  همین مسیر روی گوشی تست‌شده فریم داد: `first frame after 515ms`، `78 frames in the first 3000ms`.
- **YUV:** `ImageReader(YUV_420_888)` مستقیم به `MediaImageBuilder` و چرخش اعلامی در
  `ImageProcessingOptions` — در تئوری سریع‌تر (بدون decode و بدون کپی بیتمپ)، ولی روی این HAL هنوز
  اندازه‌گیری نشده؛ وقتی مدل واقعاً صدا زده شود، تفاضلش در `probe: … ms each` دیده می‌شود.

`BaseOptions.Delegate.GPU` امتحان می‌شود و اگر رام رد کند به CPU برمی‌گردد، و خط
`model: ready face=live hand=live (GPU/CPU)` می‌گوید کدام اسلات واقعاً پر است و کدام delegate آمده.
در حالت نشانگر مدل چهره هر فریم و مدل دست هر N فریم اجرا می‌شود؛ پینچ صدها میلی‌ثانیه طول می‌کشد،
پس نمونه‌برداری با نصف نرخ چیزی کم نمی‌کند. میانگین میلی‌ثانیهٔ هر مدل در تب تشخیص چاپ می‌شود.

**باگی که همین خطوط پیدایش کردند:** مدل ساخته و در لاگ گزارش می‌شد ولی به فیلد کلاس **assign**
نمی‌شد؛ هر فریم روی `face ?: return` بی‌صدا برمی‌گشت و هیچ مدلی صدا زده نمی‌شد، در حالی که ۲۶ فریم
در ثانیه دیکد می‌شد. `model: hand on CPU` هم درست بود هم بی‌فایده. از آن روز لاگ، *اسلات زنده* را
می‌گوید نه *ساختِ مدل* را.

## ساخت

بیلد فقط در GitHub Actions ساخته می‌شود (این ریپو عمداً روی ماشین سازنده کامپایل نمی‌شود):

```
gradle :app:assembleRelease      # همان کاری که workflow می‌کند
bash tools/run-tests.sh          # ۳۹ assertion روی منطق خالص، بدون اندروید
node tools/scan.js app/src       # بالانس براکت/پرانتز + کلمهٔ کلیدی به‌عنوان نام
```

`com.google.mediapipe:tasks-vision:0.10.29` از `google()` می‌آید. مدل‌ها داخل ریپو هستند:
`app/src/main/assets/hand_landmarker.task` (۷٫۸ مگ) و `face_landmarker.task` (۳٫۸ مگ) از
`storage.googleapis.com/mediapipe-models/...`. هر دو `.task` یک zip با `.tflite`های داخل‌اند،
برای همان `noCompress += "task"` در `app/build.gradle.kts`.

## نصب و اولین اجرا

1. APK را نصب کن. مجوز Accessibility در Play Store فقط برای «ابزار کمکی» مجاز است، پس این اپ
   sideload می‌شود.
2. تب خانه → «تنظیمات دسترسی» → «اشاره» → روشن. این یکی را **باید با انگشت** بزنی.
3. مجوز دوربین، و برای دیدن مکان‌نما/حلقه مجوز پنجرهٔ شناور.
4. «روشن کردن اشاره» → سر جایی باشد که دوربین ببیند → دو پینچ برای تنظیم نقطهٔ مرجع.
5. تب تشخیص: هر خط یک علت را می‌گوید؛ جای خالی یعنی آن مسیر اصلاً اجرا نشده.

## محدودیت‌ها

دیالوگ‌های اجازه و صفحهٔ تنظیمات دسترسی، پنجره‌های `FLAG_SECURE`، کیبورد باز، دکمه‌های فیزیکی،
و نور کم — با جزئیات در تب راهنما.

pointer/PointerFilter.kt    فاصلهٔ سر از نقطهٔ مرجع → سرعت مکان‌نما (ای‌ام‌ای + ددزون + سقف)

pointer/CursorOverlay.kt    نقطه، حلقه، و پرشدنِ آبِ خودِ کنترل
sense/CameraSource.kt       Camera2 YUV → MediaPipe (چهره و دست، delegate با fallback)
inject/Synth.kt             ژست → Path/StrokeDescription (duration = سرعت = fling)
inject/AirInputService.kt   صف تزریق + hit-test درخت accessibility

tools/                      ثابت‌های JVM و اسکن ایستا؛ CI اول این‌ها را می‌گیرد بعد APK
